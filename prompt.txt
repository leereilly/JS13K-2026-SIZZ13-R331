# Create a polished, seamlessly looping js13kGames 2026 highlight reel with FFmpeg

I have 13 gameplay video clips representing the top 13 winners of js13kGames 2026. The theme was **Unicorns & Rainbows**.

I want a polished, professional highlight reel that feels like a GitHub Universe or indie game showcase video.

The main improvements I want are:

1. A beautifully designed, animated lower third for every game.
2. Smooth, understated transitions between games.
3. A genuinely seamless video and audio loop that transitions from the 13th game back to the 1st.
4. High-quality output suitable for X/Twitter, GitHub, and event displays.

**Important:** Modify and improve my existing implementation rather than rewriting everything unnecessarily. The existing `make-montage.sh` invokes `scripts/montage.py`. Inspect that Python implementation before making changes.

## 1. Inputs and project inspection

My project contains:

- `videos/`: 13 gameplay clips.
- `data.csv`: placement, game titles, and GitHub usernames.
- `assets/octocat.png`: the GitHub Octocat logo.
- `make-montage.sh`: the existing command-line entry point.
- `scripts/montage.py`: the video generation implementation.

The expected command is:

`./make-montage.sh videos/ data.csv output.mp4`

Before making changes:

- Inspect the actual project and relevant files.
- Examine the CSV columns and determine how filenames map to game titles.
- Use ffprobe to inspect every clip's dimensions, duration, frame rate, codecs, and audio streams.
- Identify any source compatibility issues.
- Choose sensible output dimensions and frame rate based on the input footage.
- Preserve the CSV order.
- Keep every game's footage in the final loop, including the portions used by transitions.

Avoid guessing filename mappings when multiple clips could match the same game.

## 2. Visual direction: Beautiful, modern lower thirds

This is the most important visual improvement.

**Design aesthetic:** GitHub Universe meets Apple TV sports graphics, with a little indie-game personality.

The lower third should look deliberately designed, not like text placed over a generic black box.

Use a restrained, premium visual style with beautiful typography, consistent alignment, generous internal spacing, and subtle visual hierarchy.

### Layout

Position the lower third toward the bottom-left of the video, respecting safe margins.

Each lower third contains:

- A circular GitHub avatar for the creator.
- The game title in large, bold Mona Sans.
- The creator's GitHub username, prefixed with `@`.
- A compact placement label such as `1ST PLACE`, `2ND PLACE`, or `13TH PLACE`.
- A small GitHub Octocat icon.

Suggested visual composition:

`[Avatar]  GAME TITLE`

`          @username   [1ST PLACE]        [Octocat]`

The game title should be the strongest visual element.

The username is smaller and secondary.

The placement should be presented as a small, elegant badge, not oversized text.

The Octocat should be recognizable but subtle. It should not compete with the game title or avatar.

### Typography

Use **Mona Sans** consistently.

At 1920×1080, aim for approximately:

- Game title: 42–48 px, bold.
- GitHub username: 24–26 px, medium.
- Placement badge: 18–21 px, semibold.
- Avatar: approximately 60–68 px diameter.
- Octocat: approximately 22–26 px.

Scale proportionally for other output resolutions.

Maintain consistent line height, letter spacing, baseline alignment, and padding.

Support long game titles without text overflow. Reduce title size gracefully or wrap to a maximum of two lines, preserving the rest of the layout.

Do not let any text or graphics overlap.

### Lower-third background

Use a **subtle translucent charcoal or graphite background**, with an elegant gradient that fades toward the right.

Preferred treatment:

- Background based on GitHub dark UI colors such as `#0D1117`.
- Approximately 78–88% opacity in the core text area.
- Soft, feathered gradient toward the transparent edge.
- Rounded corners, approximately 14–18 px.
- Extremely subtle light border or highlight.
- Very soft drop shadow to separate the panel from gameplay.
- Optional 3–4 px vertical accent line in GitHub green (`#7EE787`).
- No heavy outlines around the text.

The result should remain readable over colorful, dark, or busy gameplay without looking like a giant opaque banner.

Avoid excessive glassmorphism, neon outlines, rainbow-colored text, thick borders, or oversized gradients.

Although the competition theme is Unicorns & Rainbows, the lower thirds should remain restrained. Let the gameplay provide the color.

### Size and positioning

For 1920×1080:

- Keep the lower third under approximately 750 px wide.
- Aim for around 130–155 px high.
- Use approximately 50–65 px left and bottom margins.
- Never occupy more than approximately 15% of the video's height.
- Keep the rest of the screen unobstructed.

Do not crop gameplay unnecessarily to make room for graphics.

If a game has important HUD elements in the bottom-left, allow its lower third to move to the bottom-right using an optional per-game position override.

Do not cover essential gameplay controls, scores, or captions.

### User avatars

Fetch each creator's avatar from:

`https://github.com/USERNAME.png`

Use the username from the CSV, removing an existing `@` prefix before building the URL.

- Download and cache each avatar locally.
- Crop it into a perfect circle.
- Preserve image quality.
- Add a subtle thin border.
- Do not stretch or distort avatars.
- If an avatar fails to download, use a tasteful fallback with the creator's initials.
- Never block the whole montage because of one missing avatar.

Do not download an Octocat automatically. Use the supplied asset, with its path configurable.

## 3. Lower-third animation

Animate the lower third in a subtle, professional way.

### Entrance

At the beginning of each game's appearance:

- Fade the lower third in over approximately 200–300 ms.
- Simultaneously move it upward approximately 12–18 px.
- Use gentle ease-out timing rather than linear or bouncy motion.
- Optionally stagger the title and secondary text by 60–100 ms.

The animation should feel smooth and deliberate.

### While playing

- Hold the lower third steadily.
- Avoid continuous pulsing, scaling, glowing, or unnecessary movement.
- Keep text readable long enough for viewers to identify each game.

### Exit

- Fade out gently over approximately 200–250 ms.
- Use a small downward movement if it improves the result.
- Coordinate the exit with the transition to the next game.

**Critical:** Avoid having two lower thirds visibly overlap during a crossfade. The outgoing lower third should disappear before the incoming lower third becomes prominent.

For the seamless loop, the first game's lower third must also be visually continuous across the exported video's beginning/end boundary.

## 4. Build graphics separately from gameplay

Favor maintainable, reproducible implementation over a complicated FFmpeg filter graph.

Use Python with Pillow, SVG rendering, or another suitable image-composition library to generate transparent lower-third assets.

Then use FFmpeg to animate and composite the overlays.

Recommended approach:

1. Read each game's metadata.
2. Download/cache its avatar.
3. Generate a transparent lower-third PNG.
4. Add its entrance, hold, and exit animation with FFmpeg.
5. Produce normalized intermediate clips.
6. Assemble those clips with transitions.

It is acceptable to use FFmpeg expressions for opacity and position.

Do not add major new dependencies without a good reason.

## 5. Gameplay presentation

The gameplay should remain the focus.

- Preserve aspect ratio.
- Normalize frame rate, pixel format, resolution, and audio.
- Use 1920×1080 at 30 or 60 fps if appropriate for the source footage.
- Prefer high-quality scaling.
- Avoid stretching or cropping important gameplay.
- For unusual aspect ratios, use a tasteful blurred extension of the same gameplay as background.
- Do not add artificial cinematic black bars unless absolutely necessary.
- Preserve each clip's timing and playback speed.

All games should remain recognizable and visually sharp.

## 6. Transitions

Use understated, polished transitions, typically around **0.65 seconds**.

Preferred transition: a smooth, short crossfade.

You may occasionally use a restrained directional push if it genuinely improves the sequence, but visual consistency is more important than having lots of different effects.

Avoid:

- Spinning transitions.
- Page curls.
- Flashy zooms.
- Artificial glitch effects.
- Excessively bright white flashes.
- Long dissolves that obscure gameplay.
- Cheesy PowerPoint-style wipes.

Use FFmpeg's `xfade` or an equivalent reliable implementation.

Transitions should overlap adjacent clips rather than lengthen the timeline.

## 7. Critical requirement: A truly seamless infinite loop

**The finished montage must be designed to repeat continuously without an obvious reset, jump, flash, audio pop, or interruption.**

The last game must transition smoothly back into the first game.

Simply adding a normal ending fade and starting again at the first frame is not acceptable.

### Recommended loop construction

Build the montage as a cyclic sequence:

`Game 1 → Game 2 → ... → Game 13 → Game 1`

Add the same approximately 0.65-second transition between Game 13 and the repeated Game 1 as between the other games.

But do not export the repeated first game in its entirety.

Instead:

1. Normalize and prepare all 13 source clips, including their lower thirds and audio.
2. Assemble the sequence of 13 clips and repeat the first clip once at the end.
3. Crossfade all adjacent clips, including Game 13 into the repeated Game 1.
4. Choose a loop seam within Game 1, ideally around 1–2 seconds into its footage, away from an active transition or lower-third animation.
5. Trim the completed cyclic montage so that it begins at that position within the original Game 1 and ends at the corresponding position within the repeated Game 1.
6. Ensure these two points refer to the same source footage timestamp, with identical overlay state and audio timeline.
7. Export only one complete cycle.

This means Game 1 is split across the file boundary, which is intentional.

When playback loops, the end of the repeated Game 1 flows naturally into the beginning of the original Game 1.

The viewer should see the complete sequence of all 13 games, including a proper Game 13 → Game 1 transition, without Game 1 playing twice in each cycle.

**Important:** Compute transition offsets using actual probed or normalized durations. Do not assume every source is exactly 13 seconds.

### Loop seam quality

Choose a seam where:

- The first game's gameplay is visually stable.
- The lower third has completed its entrance animation.
- There is no scene change or unusually abrupt camera movement.
- Both sides have matching overlay, avatar, typography, and visual state.
- Audio remains continuous.

Do not place the loop boundary in the middle of a title animation, dissolve, or a fade to black.

The final frame and opening frame should represent consecutive moments of the same gameplay sequence.

Verify the boundary at the final encoded frame rate, not just with approximate timestamps.

### Audio looping

Apply the same cyclic approach to audio.

- Normalize audio to stereo, 48 kHz.
- Handle silent clips by generating silent audio.
- Use short audio crossfades between games where appropriate.
- Ensure the final audio sample flows cleanly into the first audio sample.
- Avoid audible clicks, pops, or volume spikes.
- Preserve audiovisual synchronization.

If optional background music is supplied, it must also loop seamlessly, with its own crossfade or appropriate musical edit.

Do not download or invent background music.
